# 第 15 章：パターンの総括 — OOP vs 関数型の比較

## はじめに

13 のデザインパターンを F# で実装してきました。この章では、OOP と関数型プログラミングにおけるパターンの違いを総括します。

## パターン対応表

| パターン | OOP の実装手段 | F# の実装手段 | コード量の変化 |
|:---|:---|:---|:---:|
| Template Method | 抽象クラス + 継承 | レコード型 + 関数フィールド | 大幅減 |
| Strategy | インターフェース + クラス | 関数（第一級値） | 大幅減 |
| Observer | Subject/Observer インターフェース | コールバック関数リスト | 減 |
| Composite | 抽象クラス + 再帰的な型階層 | 判別共用体 + パターンマッチング | 大幅減 |
| Iterator | IEnumerable/IEnumerator | seq { } 式 + Seq モジュール | 大幅減 |
| Command | ICommand インターフェース | レコード型 + 関数フィールド | 減 |
| Adapter | Adapter クラス | アダプター関数 | 大幅減 |
| Proxy | Proxy クラス | Lazy<T> + 関数ラッパー | 減 |
| Decorator | Decorator 基底クラス + 継承 | 関数合成（>>/List.fold） | 大幅減 |
| Singleton | static + private コンストラクタ | モジュールレベル let 束縛 | 大幅減 |
| Factory | Factory クラス + クラス階層 | 判別共用体 + ファクトリ関数 | 大幅減 |
| Builder | Builder クラス + fluent API | パイプライン / CE | 減 |
| Interpreter | Expression クラス階層 | 判別共用体 + 再帰関数 | 大幅減 |

## F# の言語機能とパターンの対応

### 判別共用体が代替するパターン

判別共用体は、OOP におけるクラス階層を 1 つの型定義で表現します。

- **Composite**: 再帰的な判別共用体で木構造を直接表現
- **Factory**: 判別共用体のケースがプロダクト、ファクトリ関数が生成を担当
- **Interpreter**: AST を判別共用体で定義し、再帰関数で評価

### 高階関数が代替するパターン

関数が第一級値であることにより、振る舞いの差し替えが関数を渡すだけで実現されます。

- **Strategy**: 関数を引数として渡す
- **Template Method**: レコード型の関数フィールドを差し替える
- **Command**: execute/undo 関数をレコードに格納

### 関数合成が代替するパターン

関数合成により、機能の積み重ねが宣言的に記述できます。

- **Decorator**: `Writer -> Writer` 型の高階関数を合成

## 「パターンが消える」とはどういうことか

GoF パターンが「消える」のではなく、パターンの**意図**は残り、**実装の定型コード**が言語機能に吸収されるのです。

- 意図は残る: 「振る舞いを差し替えたい」「木構造を統一的に扱いたい」
- 実装が簡素化される: クラス階層 → 判別共用体、インターフェース → 関数

## まとめ

- F# では GoF パターンの大半が言語機能で自然に表現される
- パターンの「意図」を理解していれば、F# のイディオムで直感的に実装できる
- OOP パターンの知識は無駄にならず、関数型での設計判断の基盤になる

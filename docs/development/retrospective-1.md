## ふりかえり（KPT）

### Keep（続けること）

1. **AI エージェントとのペアプログラミング**: 一次資料の読み込み → 実装 → テスト → 記事執筆のサイクルを高速に回せた
2. **module による名前空間分離**: パターン間のクラス名衝突（例: `Report` が Template Method と Strategy の両方に存在）を module で解決した。後続言語でも同じアプローチを踏襲する
3. **TDD ファースト**: テストを先に書いてから実装することで、記事のコード例とテストの整合性が保証された
4. **一次資料の活用**: `tmp/ruby-design-pattern/` の既存実装を参照しつつ Ruby 3.x に近代化することで、品質を保ちながら効率的に進められた

### Problem（問題点）

1. **ブランチカバレッジ 76.92%**: 行カバレッジ 96.87% に対し、ブランチカバレッジは 80% 目標を下回った。特に Interpreter パターンの条件分岐カバレッジが不足している
2. **Strategy パターンの文字化け**: Unicode 文字列が Write ツールで化ける問題が発生し、Unicode エスケープ（`\uXXXX`）で回避した。後続言語でも注意が必要
3. **PlantUML シンタックスエラー**: Singleton 章で `module` キーワードを PlantUML で使用してエラーになった。PlantUML のクラス図では `class + <<module>>` ステレオタイプを使う必要がある
4. **コミット粒度**: 実装と記事を 1 つの大きなコミット（`69d5a25`）にまとめてしまった。本来は部ごと（第 2 部、第 3 部、第 4 部）に分割すべきだった

### Try（次に試すこと）

1. **ブランチカバレッジの改善**: IT-2（Java）では条件分岐を意識したテストケースを追加し、ブランチカバレッジ 80% 以上を達成する
2. **部ごとのコミット**: 第 2 部・第 3 部・第 4 部をそれぞれ独立したコミットにする
3. **PlantUML の事前検証**: 記事作成後に PlantUML のシンタックスを確認するステップを追加する
4. **MkDocs プレビュー確認**: 記事完成後に `npm run docs:serve` でプレビュー確認する（今回は省略した）
5. **Java 版のテンプレート確立**: Ruby 版の構成をベースに、Java 版（IT-2）の記事・実装テンプレートを早期に確立する
